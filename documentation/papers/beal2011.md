This thesis does not use one vehicle model everywhere. The nonlinear simulation
model, the prediction model and the driver-intent reference model have distinct
jobs. In particular, a linear prediction model does not imply linear tires in
the physical simulation.

## Tire equation and numerical use

Let `C` be axle cornering stiffness, `D=mu*Fz`, `R=mu_slide/mu`, and
`t=tan(alpha)`. Eq. 2.1 gives

\[
F_y=-Ct+\frac{C^2}{3D}(2-R)t|t|
       -\frac{C^3}{9D^2}(1-2R/3)t^3.
\]

The sliding branch is implemented with the restoring sign
`Fy=-R*D*sign(alpha)`. Reducing `D` to `sqrt((mu*Fz)^2-Fx^2)` is the
approximation in Eq. 2.8; the full combined-slip model in Eq. 2.7 additionally
needs longitudinal slip/wheel rotation. `brush()` implements the lateral law,
and `derated_capacity()` exposes the Eq. 2.8 approximation. The default
constant-speed demonstration has no requested longitudinal tire force.

Two interpretation choices are explicit. Eq. 2.2 prints `alpha_slide=3D/C`,
whereas the cubic is in `tan(alpha)`. The code switches at
`abs(tan(alpha))=3D/C`, equivalently `atan(3D/C)`, to preserve continuity.
Eq. 2.3 prints the sliding magnitude; the code supplies its sign. These are
documented interpretations, not a claim of literal transcription of both printed
expressions. Tests check odd symmetry, small-slip stiffness and continuity.

No differential equation is needed to evaluate this tire law. The inverse mapping
is different: `inverse_brush()` uses a bracketed root solve restricted to the
branch up to the peak angle, as motivated on printed p. 23. Restricting the branch
is essential when peak and sliding friction differ and force is not globally
one-to-one in slip angle.

## Vehicle and MPC equations

With constant positive longitudinal speed `U`, small-angle sideslip
`beta=Uy/U`, and axle slip angles

\[
\alpha_f=\beta+ar/U-\delta,\qquad \alpha_r=\beta-br/U,
\]

the lateral dynamics (2.15) are

\[
\dot\beta=(F_{yf}+F_{yr})/(mU)-r,
\qquad \dot r=(aF_{yf}-bF_{yr})/I_z.
\]

The code embeds these two states in world pose `[X,Y,psi,beta,r]` to use
`PeriodicTrack`. It integrates the nonlinear bicycle with RK4. This world-pose
adapter is an addition to the thesis's two-state prediction model.

The MPC replaces the front force law with the decision variable `Fyf` and takes
a first-order Taylor expansion of the rear force at the current slip angle:

\[
F_{yr}\approx \bar F_{yr}-\widetilde C_r(\alpha_r-\bar\alpha_r),
\qquad \dot x=Ax+BF_{yf}+d.
\]

`Bicycle.afi()` implements Eq. 2.21; `tustin()` converts it into discrete affine
dynamics. This is a numerical discretization, separate from evaluating tire
forces and separate from solving the optimization problem.

Chapter 4, especially Eqs. 4.2-4.3 (printed pp. 60-61 / PDF 77-78), minimizes
state deviation from the driver's linear-model response, control effort and
an L1 slack penalty, subject to affine dynamics, front-force and force-slew limits,
and soft bounds on yaw rate and rear slip:

\[
|r|\le r_{\max}+s_r,\qquad
|\beta-br/U|\le\alpha_{r,\max}+s_\alpha.
\]

The implemented horizon is 15 steps of 10 ms, matching Sec. 4.1.5. The first
prediction step uses the already applied force for computation-delay compensation.
The affine offset is retained in this first step as well. Front force is inverted
to a steering command for the next step. This is a convex QP once the measured
rear linearization and limits are fixed; IPOPT is used here as an available solver,
not the original generated real-time C solver. Timing equivalence is not claimed.

## Code map and repository integration

| Code | Purpose |
|---|---|
| `tracklab/paper_models/beal2011.py: brush, peak, inverse_brush` | Nonlinear tire evaluation and force-to-slip inversion |
| `Bicycle.rhs`, `Bicycle.step` | Constant-speed nonlinear simulation and RK4 |
| `Bicycle.afi`, `linear_driver_model` | Separate prediction and driver-intent models |
| `EnvelopeMPC` | Delayed affine prediction, quadratic objective, soft envelope constraints |
| `run_paper_beal.py` | Road geometry -> illustrative driver -> envelope controller -> vehicle |
| `tests/test_paper_beal.py` | Force properties, inverse branch, AFI consistency, independent integration, MPC solve |

The road-following driver in the runner uses curvature, heading error and lateral
offset. It is a new illustrative driver; it is not a human-driver reproduction.
The physical constants and optimization weights are illustrative defaults, not
identified parameters from the P1 test vehicle. The existing tracking NMPC,
steering actuator and native C++ bridge are not used for this new experiment.

## Run and validation

```bash
python -m pip install -r requirements-driving.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run_paper_beal.py --steps 200
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest discover -s tests -p 'test_paper_beal.py' -v
```

The six model/controller tests pass. A 200-step, 2-second road run completed
200 successful optimizations; maximum cross-track error was about 0.047 m.
This short run exercises the integration, not full-lap or limit-handling behavior.
The 18 existing road tests and 13 existing Python-driving tests also pass.

## Fidelity limits

Not implemented: the four-wheel yaw-roll plant, wheel-spin combined-slip law,
roll-control extension, pneumatic-trail friction estimator and experiment-specific
calibration. A `mu` parameter is not an online friction estimator. Soft constraints
can permit envelope violations, so the invariance arguments in Sec. 4.3 do not
automatically certify this adaptation with different parameters and a synthetic
driver. This controller is for handling assistance, not minimum lap time.
