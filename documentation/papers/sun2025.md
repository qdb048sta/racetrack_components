## There are two different vehicle model families

Chapters 3 and 4 consider longitudinal driving. Chapter 3 has two in-wheel motors;
Eq. 3.4 on p. 43 is

\[
\dot p=v,\qquad
m\dot v=2\eta_t T/r-C_dv^2-mg\sin\theta-mgC_f\cos\theta.
\]

Chapter 4's Eq. 4.1 on p. 66 uses `eta_t*T/r` with its total-torque convention.
The code represents the difference explicitly through `motors=2` or `motors=1`.
`Cd` here already multiplies `v^2` to produce force; it is not directly the
dimensionless aerodynamic coefficient used in `0.5*rho*Cd*A*v^2`.

There is no lateral tire force/slip curve in these equations. Tire-related
quantities are rolling resistance, wheel radius and the driving/braking force.
This should not be described as a linear lateral tire model.

Chapter 5 uses the kinematic bicycle (Eq. 5.1, p. 106):

\[
\beta=\arctan\left(\frac{l_r}{l_f+l_r}\tan\delta\right),
\quad \dot X=v\cos(\psi+\beta),\quad\dot Y=v\sin(\psi+\beta),
\]
\[
\dot\psi=\frac{v\tan\delta\cos\beta}{l_f+l_r},
\quad\dot v=a,\quad\dot\delta=\omega.
\]

The state is `[X,Y,psi,v,delta]` and input is `[a,omega]` in this code. The paper
lists the same state components in a different order in the OCP description.
Beta is determined geometrically; it is not an independently integrated sideslip
state and there is no Pacejka/Fiala tire. Unlike the repository's dynamic bicycle,
this model cannot predict a loss of lateral grip. It is useful where geometric
coordination and computational cost dominate.

## Why the spatial transformation is useful

With kinetic energy `E=m*v^2/2`, positive speed and `d/ds=(1/v)d/dt`,

\[
E'=2\eta_tT/r-2C_dE/m-mg(\sin\theta+C_f\cos\theta),
\quad \Delta t'=\sqrt{m/(2E)}-1/v_0.
\]

These are Eqs. 3.6-3.7 (pp. 44-45); Chapter 4's equivalents are Eqs. 4.5-4.9
(pp. 68-69). Energy dynamics are affine, while headway has reciprocal speed.
Introducing a virtual input `xi` gives

\[
\Delta t'=\xi-1/v_0,\qquad \xi\ge\sqrt{m/(2E)}.
\]

The right side is convex for positive energy. This produces a convex feasible
set with affine dynamic constraints. **A solution is physically equivalent only
when the inequality is tight.** A small optimization residual does not establish
that equality. The thesis discusses legitimacy of relaxed solutions, including
the weights and assumptions in Sec. 4.4.

The motor power fit (3.2) is `P=a*T^2*v+b*T*v+c*v`; after division by speed,
the spatial energy objective becomes a quadratic in torque (3.3). The fitted
coefficients/efficiency map are not recovered or claimed by this implementation.

## MPC algorithms in the thesis

| Chapter | Algorithm and location | Essential extra ingredients |
|---|---|---|
| 3 | Learning-based ecological following; MFST prediction in Sec. 3.3.1, robust learning-in-the-loop MPC in Sec. 3.3.2, pp. 50 onward | Learned predecessor speed; bounded modeling/prediction error; speed-dependent tube design |
| 4 | Tube-based distributed platooning; Eqs. 4.11-4.31, pp. 70-77; Algorithm 3 | Observer, stabilizing ancillary gain, invariant error sets, tightened constraints, predecessor-follower exchange of shifted assumed trajectories, terminal set |
| 5 | APF planning plus distributed trajectory tracking; OCP 5 Eq. 5.11 p. 112, Algorithm 4 p. 113 | Reconfigurable neighbor graph, obstacle information, collision/consistency constraints, terminal position disk |

For Chapter 3, the nominal prediction `xbar+=A*xbar+B*ubar+gamma` is paired
with `u=ubar+K*(x-xbar)` (3.19). The error satisfies
`e+=(A+BK)*e+d` (3.20); invariant error set `E` is used to tighten state and
input constraints (3.21-3.22). The nominal MPC and the ancillary feedback have
different roles. Simply adding a terminal penalty does not implement this tube.

Chapter 4 adds measurement noise and an observer; it communicates shifted
assumed trajectories (4.23-4.25), penalizes differences from those trajectories
and desired headway/energy (4.31), and constrains the terminal state (4.30).
These ingredients are relevant to the stated recursive-feasibility/robustness
analysis and cannot be omitted while retaining its guarantees.

OCP 5 minimizes position tracking distance subject to discretized kinematics,
state/input limits, collision constraints and a terminal disk. It is not a
dynamic racing controller or a minimum-time objective.

## Executable scope and integration

`tracklab/paper_models/sun2025.py` contains:

- `Longitudinal.time_rhs` and `spatial_rhs`: physical equations with explicit
  torque convention and positive-speed domain.
- `SpatialFollowingMPC`: nominal spatial relaxation, using scaled energy for
  conditioning. It has headway/speed/torque/rate bounds and illustrative quadratic
  tracking/control costs with a positive `xi` penalty. It is **not** Eq. 4.26's
  complete distributed robust design.
- `KinematicBicycle`: Eq. 5.1, shared numeric/CasADi equations.
- `KinematicMPC`: Euler prediction as in OCP 5, state/input constraints,
  position objective, terminal disk, optional externally provided neighbor
  trajectories and disk separation. The objective norm is smoothed with `1e-8`
  under its square root and a small control regularizer is added.

`run_paper_sun.py` composes the road and these controllers. Kinematic mode takes
its reference, normals and widths from `PeriodicTrack`; it does not implement
the APF planner. Following mode samples the road's surface height to form slope
and uses an explicitly supplied constant-speed predecessor. It propagates the
physical headway equality with RK4, never the fictitious input `xi` as a plant
actuator. The current CSV has a flat assumed surface, so slope is zero by default.

### Explicit relaxation failure handling

The nominal relaxation can be loose under the demonstration weights. The solver
returns its gap `xi-1/v`. If its maximum magnitude exceeds `1e-4 s/m`, the default
implementation solves a second problem with physical equality `xi=1/v` and
reports `physical_fallback=True`. This second solve is nonlinear and nonconvex.
It is a practical adaptation, **not** the thesis's convexity/legitimacy proof.
Call `solve(...,allow_physical_fallback=False)` to inspect the relaxed candidate
without repair. Logs preserve both candidate gaps and the fallback count.

## Run and validation

```bash
python -m pip install -r requirements-driving.txt
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run_paper_sun.py --steps 30
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run_paper_sun.py --mode following --steps 30 --output outputs/papers/sun_following
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m unittest discover -s tests -p 'test_paper_sun.py' -v
```

Six tests cover the energy chain rule, positive-speed restriction, analytic
kinematic turning, independent integration, terminal-disk solve, tightness
diagnostics and an intentionally loose case that exercises the physical fallback.
The 30-step kinematic run completes with about 0.0068 m maximum lateral offset
on its short tested segment. The 30-step following run completes; 24 steps use
physical fallback under these weights. This is evidence against calling the
nominal demonstration an always-exact convex reformulation. The existing 31
road/Python-driving tests pass.

Not implemented: trained MFST weights/data pipeline, fitted motor efficiency,
adaptive invariant tubes, observer, communication protocol, distributed assumed
trajectory update, APF formation planning, experimental calibration and the
associated guarantees. The optional neighbor constraints exercise a local
tracking interface; they do not by themselves create the distributed algorithm.
